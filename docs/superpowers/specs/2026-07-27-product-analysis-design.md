# Product Analysis Skill设计规格

## 1.目标

新增独立的`product-analysis`skill，用于回答公司真正卖什么、产品如何被设计和交付、单位经济如何形成、客户为何购买、竞争优势相对谁成立，以及这些优势如何映射到财报。

该skill必须把产品事实、流程事实和竞争判断连成可复核证据链，不把高毛利、品牌知名度或管理层宣传直接当作竞争力。

## 2.职责边界

`product-analysis`负责：

- 识别核心产品、服务、客户场景和利润池。
- 拆解设计、采购、生产或服务交付、质检、渠道、售后和反馈流程。
- 分析流程周期、产能、良率、瓶颈、成本结构、库存和资本需求。
- 解释客户选择目标产品而非替代品的可观察原因。
- 在可比竞争集合中判断目标公司的相对位置和与龙头的差距。
- 把产品结论映射到收入、毛利、费用、周转、现金流和资本开支。
- 输出结构化的产品竞争力事实和失效条件。

`product-analysis`不负责：

- 给出最终护城河宽度。该结论继续由`value-profile`的§3和`moat-framework.md`负责。
- 评价管理层诚信或财务造假风险。
- 给出估值和买入价格。
- 把管理层口号、媒体排名或单一毛利率直接升级为竞争优势。

## 3.文件结构

新增：

```text
.claude/skills/product-analysis/
├── SKILL.md
└── references/
    ├── process-playbooks.md
    └── value-mechanisms.md
```

修改：

```text
.claude/skills/value-profile/SKILL.md
.claude/skills/value-profile/template-zh.md
tests/unit/skills/test_financial_skill_contracts.py
```

`SKILL.md`保持在500行以内，只保存运行模式、核心流程、输出契约和失败规则。

`process-playbooks.md`保存制造业、消费品、软件与互联网、零售、平台及专业服务的流程拆解方法。

`value-mechanisms.md`保存需求侧价值机制、选择条件和财报验证方法。它是候选工具箱，不是必须全部填写的清单。

## 4.运行模式

### 4.1 Mode A

用户直接提供ticker时默认进入Mode A。

示例：

```text
/product-analysis 600519.SH
/product-analysis 09992.HK --as-of 2026-07-27
```

Mode A独立完成资料准备、分析和复核，输出：

```text
profiles/<ticker>-product-<YYYY-MM-DD>[-vN].md
```

### 4.2 Mode B

`value-profile`提供`--target-profile`时进入Mode B。Mode B使用父skill已绑定的年报和事件证据，不直接修改profile，只返回：

- `draft_sections`
- `product_facts`
- `process_facts`
- `competition_facts`
- `moat_handoff`
- `citations`
- `warnings`
- `unresolved_items`
- `terminal_status`

Mode B拥有`part1/§1.1`和`part1/§1.3`的草稿生成权。`moat_handoff`只向§3提供事实，不包含`宽/中/窄/弱`结论。

父skill复核后通过既有CAS机制原子写入目标profile。Mode B无论`--auto`还是`--interactive`都不直接写文件，也不显示第二套确认菜单。

## 5.分析流程

### 5.1确定产品边界

先按客户用途、价格带、交付方式和经济模型划分产品，不完全依赖公司披露的分部名称。

核心产品集合按以下优先级确定：

1. 对收入、毛利或经营现金流有重大贡献。
2. 决定客户选择和公司战略位置。
3. 占用关键产能、库存、研发或渠道资源。

不得机械要求单一产品贡献超过50%营收。多产品公司可以形成核心产品组合，但必须解释组合内部的交叉销售、成本共用或生态关系。

### 5.2建立产品利润地图

逐产品或产品组列出：

- 收入及占比。
- 增速和量价拆分。
- 毛利额和毛利率；未披露毛利额时明确缺口。
- 客户、地域和渠道结构。
- 资本开支、库存或营运资金占用。
- 生命周期位置和主要替代品。

核心排序优先使用毛利额和现金贡献，不因高收入低利润业务掩盖真正利润来源。

### 5.3拆解设计与交付流程

先选择适用流程类型，再逐步拆解。

制造及消费品至少覆盖：

```text
需求洞察→产品定义→研发或配方→原料与供应商→试制→量产→质检→仓储→渠道→售后与反馈
```

软件与互联网至少覆盖：

```text
需求发现→产品设计→开发→测试→部署→获客→使用与服务→数据反馈→迭代
```

零售、平台和专业服务至少覆盖：

```text
供给组织→匹配或选品→获客→交易或履约→质量控制→售后→留存与复购
```

每个关键步骤填写：

- 输入和输出。
- 公司、供应商或渠道中的责任主体。
- 时间周期。
- 主要固定成本和变动成本。
- 产能、良率、吞吐量或人员利用率。
- 质量控制点。
- 最难复制的能力。
- 单点故障和扩产约束。
- 来源与证据等级。

不知道的成本不得伪造。可根据公开输入建立区间估算，但必须列出公式、假设和敏感性，不得把估算写成公司披露值。

### 5.4分析单位经济

制造业优先分析单件或单位产能经济；服务和软件优先分析单客户、单订单、单门店、单点位或单次履约经济。

至少解释：

- 单位收入如何形成。
- 直接材料、人工、制造费用或履约成本如何形成。
- 获客、渠道、售后和退货成本是否计入。
- 规模扩大时哪些成本下降、哪些成本不会下降。
- 产能利用率、良率、复购率或留存率对利润的敏感性。
- 单位经济与报表毛利、销售费用、存货、合同负债和现金流的勾稽关系。

### 5.5识别客户购买标准

分别识别购买者、使用者和付款者，明确：

- 使用场景和待完成任务。
- 不购买时的替代方案。
- 选择标准及其排序。
- 试错成本和转换成本。
- 价格敏感度与愿付溢价。
- 复购、留存或推荐的可观察证据。

不得把品牌知名度等同于购买理由。必须解释品牌具体降低了什么风险、节省了什么时间或提供了什么身份信号。

### 5.6建立竞争阶梯

竞争集合同时包含：

- 同客户、同场景、同价格带的直接竞品。
- 能完成同一任务的替代方案。
- 适用时的行业龙头或用户心智上限。

比较维度从产品性能、质量稳定性、设计速度、成本、交付周期、渠道、服务、信任、生态和供应链中选择与购买决策最相关的项目。

若目标不是龙头，必须说明：

- 目标公司领先哪些对手。
- 落后龙头的具体环节。
- 差距来自产品、成本、流程、渠道还是用户认知。
- 差距正在扩大、缩小还是无法判断。

不同价格带或不同客户群的公司不得仅因行业相同而强行比较。

### 5.7选择需求侧价值机制

从`value-mechanisms.md`选择最重要的2至3项机制，只有证据充分时才选择：

- 功能和性能优势。
- 可靠性与信任。
- 时间节省和便利。
- 情绪回报和体验。
- 身份表达和社群认同。
- 稀缺性和时间价值。
- 数据、生态和转换成本。
- 网络密度或供需匹配效率。

每项机制必须有行为证据和财务证据。毛利率超过某个数值不能单独证明情绪、身份或稀缺价值。

### 5.8财报映射与失效测试

把每个关键判断至少映射到一个可验证指标：

- 产品溢价：价格、销量、毛利率及促销变化。
- 信任：复购、留存、退货、投诉、质保或渠道稳定性。
- 效率：单位成本、周转、履约成本、产能利用率或人员利用率。
- 生态和转换成本：留存、交叉购买、递延收入或迁移成本。
- 供应链能力：交付周期、良率、库存、预付款、供应商集中度和资本开支。

至少构造两个可证伪失效条件，覆盖技术替代、竞争者复制、原料或人工成本、供应链中断、渠道库存、价格倒挂、消费降级或监管变化。

## 6.证据规则

来源优先级：

1. 交易所文件、招股书、年报、官方产品规格、监管文件和公司可核验运营数据。
2. 供应商或客户官方资料、专利、认证、渠道价格和可复核行业数据。
3. 高质量行业研究和可靠媒体。
4. 用户评论、论坛或社交数据，仅作线索，不单独支持关键结论。

证据等级：

- `高`：主要结论由一手来源直接支持，流程、期间和口径可复核。
- `中`：一手来源不完整，但至少两个独立来源或可复算代理指标方向一致。
- `低`：主要依赖单一二手来源、不可复核访谈或弱代理指标。
- `需人工`：来源冲突、关键字段缺失或无法区分披露值与估算值。

每个流程步骤、竞争比较和价值机制都必须标注证据等级。低等级证据不得支撑“领先”“难以复制”或“具有定价权”等强结论。

## 7.标准输出

Mode A报告及Mode B草稿按以下顺序输出：

1. `一句话产品本质`
2. `核心产品与利润地图`
3. `设计、生产或服务交付流程`
4. `单位经济与财报勾稽`
5. `客户任务与购买标准`
6. `竞争阶梯与龙头差距`
7. `核心价值机制`
8. `流程和竞争力失效条件`
9. `待补证据与跟踪指标`
10. `机器引用清单`

一句话结论必须同时包含产品、客户任务和经济来源，不使用夸张修辞代替事实。

## 8.失败处理

以下情况不得输出完成结论：

- 无法确定核心产品及其收入或利润贡献。
- 制造业缺少生产流程且未明确标为待补。
- 服务或软件公司缺少交付流程且未明确标为待补。
- 单位成本估算没有公式、输入来源或敏感性。
- 竞争结论没有直接竞品或替代方案。
- 非龙头公司没有分析与适用龙头的差距。
- 需求侧价值机制没有同时对应行为证据和财务证据。
- Mode B的引用、manifest路径或SHA-256与Part 0绑定不一致。

自动模式最多针对明确缺口重查两次。仍无法闭合时返回`terminal_status=pending`和`unresolved_items`，不得编造或降低完成标准。

## 9.测试策略

契约测试至少验证：

- skill能被产品、生产流程、服务流程、单位经济、竞争力等请求触发。
- 直接ticker默认为Mode A，`--target-profile`进入Mode B。
- Mode B不直接写profile，父skill是唯一写入者。
- 制造业和服务业分别具有强制流程字段。
- 核心产品识别不依赖固定50%阈值。
- 高毛利不能单独证明品牌、身份或稀缺性。
- 未披露成本只能输出带假设的区间估算。
- 竞争集合包含直接竞品、替代方案和适用龙头。
- 非龙头必须输出龙头差距。
- 价值机制只选择2至3项且必须映射财报。
- 最终护城河标签仍由`value-profile`负责。
- 所有关键结论都有引用和显式证据等级。
- 中文字符之间不存在不恰当空格。

基准失败场景使用茅台、泡泡玛特和制造供应链公司三类提示，验证没有skill时容易出现的三类问题：只讲品牌故事、跳过生产流程、孤立赞美而不做相对比较。

## 10.验收标准

- `SKILL.md`不超过500行并通过skill快速验证。
- 新增契约测试先失败，再在实现后通过。
- 现有财务skill契约测试全部通过。
- `value-profile`能够确定性调用Mode B并消费`moat_handoff`。
- 任何强竞争力结论都能追溯到产品事实、流程事实、相对比较和财报指标。
- 运行中文间距检查，两个中文字符之间无不恰当空格。
